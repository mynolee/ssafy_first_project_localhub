## 1. 프로젝트 개요

### 1.1 목적

In지도는 전국 5개 권역의 공공 관광 데이터와 지역 커뮤니티 게시글을 한 화면에서 탐색하고, 제공 데이터 범위 안에서 AI 챗봇의 안내를 받을 수 있는 웹 서비스입니다. 회원가입 없이 게시글을 작성할 수 있으며, 장소 탐색·지도·게시판·챗봇을 하나의 Vue 3 SPA로 제공합니다.

### 1.2 대상 사용자

- 여행지, 음식점, 축제, 문화시설 등 지역정보를 찾는 사용자
- 지역 경험과 관광 팁을 익명으로 공유하려는 사용자
- 제공된 장소 및 게시글을 근거로 간단한 추천을 받고 싶은 사용자

### 1.3 시스템 구성

```text
브라우저(Vue 3 SPA)
  ├─ Vue Router: URL 및 화면 상태
  ├─ Axios: REST API 요청
  └─ Leaflet + OpenStreetMap: 지도 표시
             ↓ HTTPS
FastAPI(Render)
  ├─ SQLAlchemy ORM
  ├─ SQLite(현재 구성)
  ├─ JSON 스냅샷 시딩
  └─ OpenAI API 호출(챗봇)
```

### 1.4 기술 스택

| 구분 | 기술 | 적용 내용 |
| --- | --- | --- |
| Frontend | Vue 3, Vite | 반응형 SPA 및 프로덕션 빌드 |
| Routing | Vue Router | History 모드, 상세·수정 URL 및 섹션 이동 |
| HTTP | Axios | 공통 API Base URL, 15초 타임아웃 |
| Map | Leaflet, OpenStreetMap | 카테고리별 마커와 지도 타일 |
| Backend | FastAPI, Pydantic | REST API, 입력 검증, 공통 응답 모델 |
| ORM / DB | SQLAlchemy, SQLite | 장소·게시글 저장 및 조회 |
| AI | OpenAI Python SDK | 검색된 장소·게시글 기반 답변 생성 |
| Deployment | Netlify, Render | 프론트엔드와 백엔드 분리 배포 |

### 1.5 범위

| 포함 기능 | 제외 기능 |
| --- | --- |
| 5개 권역·8개 카테고리 장소 조회 | 회원가입, 로그인, JWT |
| Leaflet 지도와 장소 상세 카드 | 댓글, 게시글 검색, 페이지네이션 |
| 익명 게시글 CRUD와 비밀번호 확인 | 날씨, 길찾기, 현재 위치 |
| 게시글 이미지, 조회수, 좋아요 | WebSocket·SSE 기반 실시간 갱신 |
| 지역 선택형 AI 챗봇 | 벡터 DB·임베딩 기반 RAG |
| 모바일 반응형 UI | 다국어 지원, 관리자 화면 |

## 2. 데이터 활용

### 2.1 서비스 권역과 카테고리

| 구분 | 값 |
| --- | --- |
| 권역(5개) | 서울, 대전·충청, 구미·경북, 광주·전라, 부산 |
| 카테고리(8개) | 관광지, 맛집, 축제, 문화시설, 여행코스, 레포츠, 쇼핑, 숙박 |

### 2.2 출처 및 적재 범위

| 제공 기관 / 데이터 | 적용 권역 | 원본 건수 | 빈 DB 초기 적재 | 라이선스 |
| --- | --- | ---: | ---: | --- |
| 한국관광공사 TourAPI 4.0 | 5개 권역 | 아래 합계에 포함 | 아래 합계에 포함 | 공공누리 제3유형 |
| 서울시 일반음식점 인허가 정보 | 서울 | 1,000건 | 품질 검사 후 적재 | 공공누리 제1유형 |
| 부산맛집정보 서비스 | 부산 | 437건 | 품질 검사 후 적재 | 공공누리 제1유형 |
| 전체 JSON 스냅샷 40개 | 5개 권역 | 14,139건 | 14,124건 | 출처별 상이 |

권역별 빈 DB 초기 적재 예상치는 서울 7,512건, 대전·충청 1,362건, 구미·경북 1,665건, 광주·전라 1,390건, 부산 2,195건입니다.

### 2.3 수집·시딩 정책

- 앱 실행 중에는 관광 공공 API를 직접 호출하지 않고 저장소의 JSON 스냅샷을 사용합니다.
- 백엔드 시작 시마다 `source_id`를 기준으로 장소를 추가·갱신하고, 이름 품질 검사를 적용합니다.
- 공급자 스냅샷에 `sync: true`가 설정된 경우 사라진 기존 공급자 레코드를 정리합니다.
- 장소 시딩은 게시글 테이블을 수정하지 않습니다. 단, DB 파일이 유지되는 경우에만 기존 게시글도 유지됩니다.
- 서울 음식점 좌표는 수집 단계에서 EPSG:5174에서 WGS84로 변환합니다.
- OpenStreetMap 지도 타일과 OpenAI 챗봇은 런타임 외부 네트워크에 의존합니다.
- 장소 카드에는 가능한 경우 제공처, 라이선스, 수집일을 표시합니다.

## 3. 화면 및 라우팅

### 3.1 SPA 구성

게시판과 지역정보 지도를 별도 페이지로 분리하지 않고 하나의 통합 메인 화면에 배치합니다. 게시판이 상단, 지도·장소 목록이 하단에 있으며 헤더는 해시(`#community`, `#discover`)를 이용해 섹션으로 이동합니다.

| 경로 | 라우트 이름 | 실제 동작 |
| --- | --- | --- |
| `/` | `home` | 통합 메인 화면 |
| `/posts` | `home` 별칭 | `/`과 같은 통합 화면 |
| `/explore` | `home` 별칭 | `/`과 같은 통합 화면 |
| `/posts/:id` | `post-detail` | 같은 화면에서 해당 게시글 행을 펼쳐 상세 표시 |
| `/posts/:id/edit` | `post-edit` | 같은 화면에서 해당 게시글의 인라인 수정 폼 표시 |
| `/?compose=1#community` | `home` + query/hash | 게시판 섹션으로 이동하고 인라인 작성 폼 표시 |

`/posts/new` 독립 경로는 구현되어 있지 않습니다. Netlify는 모든 SPA 경로를 `index.html`로 rewrite하여 직접 접속과 새로고침을 지원합니다.

### 3.2 공통 UI

- 상단 헤더: 게시판·지역정보 섹션 이동, 글쓰기 진입
- 본문 상단: 지역 커뮤니티 게시판
- 본문 하단: 권역·카테고리 필터, Leaflet 지도, 장소 목록·상세
- 우측 하단: 전 화면 공통 플로팅 챗봇
- 모바일: 내비게이션, 게시판, 지도·목록, 챗봇을 반응형으로 표시

## 4. 핵심 기능 명세

### 4.1 지도 시각화 및 장소 탐색

| ID | 기능 | 동작 및 조건 |
| --- | --- | --- |
| MAP-01 | 권역 선택 | 서울을 초기값으로 사용하며 5개 권역 중 하나를 선택합니다. |
| MAP-02 | 카테고리 필터 | 전체 또는 8개 카테고리로 장소를 필터링합니다. |
| MAP-03 | 장소 조회 | `region`, `category`, `limit=200`으로 백엔드에 요청합니다. |
| MAP-04 | 조회 제한 | API는 유효한 한국 좌표만 이름순으로 최대 200건 반환하며, 입력 `limit`은 1~500으로 제한합니다. |
| MAP-05 | 지도 마커 | 좌표가 있는 응답 장소를 카테고리별 색상의 원형 마커로 표시합니다. |
| MAP-06 | 목록 표시 | API 응답 중 처음 20개 장소를 우측 카드 목록으로 표시합니다. |
| MAP-07 | 장소 선택 | 마커 또는 카드를 선택하면 지도를 확대하고 이미지·주소·설명·전화·출처 등을 상세 카드로 표시합니다. |
| MAP-08 | 되돌아가기 | 상세 카드의 되돌아가기 동작으로 목록과 이전 지도 범위를 복원합니다. |

### 4.2 익명 커뮤니티

| ID | 기능 | 동작 및 조건 |
| --- | --- | --- |
| POST-01 | 목록 조회 | 최신 작성일·ID 순으로 조회하며 권역·카테고리 필터를 적용합니다. |
| POST-02 | 상세 조회 | 글 내용과 이미지를 표시하고 상세 API 호출 때마다 조회수를 1 증가시킵니다. |
| POST-03 | 작성 | 로그인 없이 지역, 카테고리, 제목, 내용, 작성자, 비밀번호를 입력합니다. |
| POST-04 | 수정 | 기존 비밀번호가 일치하고 수정 필드가 하나 이상일 때만 수정합니다. |
| POST-05 | 삭제 | 비밀번호 확인 대화상자에서 일치한 경우 게시글을 삭제합니다. |
| POST-06 | 이미지 | JPEG, PNG, WEBP, GIF 파일을 최대 5MB까지 첨부하며 새 파일은 기존 파일을 교체합니다. |
| POST-07 | 좋아요 | 인증 없이 서버 카운트를 증가·감소하며 0 미만으로 내려가지 않습니다. 브라우저의 선택 상태는 `localStorage`에 저장합니다. |
| POST-08 | 보존 제한 | 새 글 작성 후 전국 합산 카테고리별 30개를 초과하면 가장 오래된 글부터 삭제합니다. |
| POST-09 | 화면 갱신 | 최초 진입, 필터 변경, 자신의 작성·수정·삭제 후 목록을 다시 조회합니다. 다른 사용자의 변경을 자동 polling하지 않습니다. |

#### 입력 제한

| 필드 | 필수 | 제한 |
| --- | --- | --- |
| `region` | 예 | 5개 권역 코드 중 하나 |
| `category` | 예 | 8개 카테고리 코드 중 하나 |
| `title` | 예 | 1~100자 |
| `content` | 예 | 1~5,000자 |
| `author` | 예 | 1~20자, 공백 입력 시 `익명` |
| `password` | 예 | 4~20자, 수정·삭제 확인용 |
| `image` | 아니요 | JPEG/PNG/WEBP/GIF, 최대 5MB |

#### 보존 제한의 정확한 범위

- 30개 제한은 지역별이 아니라 모든 권역을 합한 카테고리별 제한입니다.
- 제한 검사는 새 글 작성 직후에만 실행합니다.
- 수정으로 다른 카테고리로 이동한 경우 제한을 즉시 재검사하지 않으므로 일시적으로 30개를 초과할 수 있습니다.

### 4.3 AI 챗봇

| ID | 기능 | 동작 및 조건 |
| --- | --- | --- |
| CHAT-01 | 챗봇 열기 | 우측 하단 플로팅 버튼으로 패널을 열고 닫습니다. |
| CHAT-02 | 지역 선택 | 전국 또는 5개 권역을 답변 범위로 선택합니다. 질문 속 지역 키워드가 선택값보다 우선합니다. |

| CHAT-04 | 검색 근거 | 단순 키워드·부분일치 검색으로 장소와 최신 게시글을 합쳐 최대 5개를 컨텍스트로 사용합니다. |

| CHAT-07 | 로컬 폴백 | `OPENAI_API_KEY`가 없으면 검색 결과 제목을 조합한 제한된 안내 문구를 반환합니다. |
| CHAT-08 | 오류 처리 | 인증·권한·모델·한도·연결 오류를 공통 API 오류로 변환합니다. |

챗봇은 임베딩 또는 벡터 데이터베이스를 사용하는 RAG가 아니라 SQL 키워드 검색 결과를 프롬프트에 포함하는 방식입니다.

## 5. 백엔드 API

### 5.1 공통 규칙

- 기본 주소: Render 서비스 Origin
- 성공 응답: `{ "success": true, "data": ..., "message": "..." }`
- 오류 응답: `{ "success": false, "data": null, "message": "...", "error": { "code": "..." } }`
- 응답 필드는 `viewCount`, `createdAt`, `imageUrl`과 같이 camelCase를 사용합니다.
- 입력 검증 실패는 `422`, 비밀번호 불일치는 `403`을 반환합니다.
- 게시글 응답에는 `password`를 포함하지 않습니다.

### 5.2 엔드포인트

| 기능 | Method | Endpoint | 주요 입력·동작 |
| --- | --- | --- | --- |
| 상태 확인 | GET | `/health` | 서버 상태와 `chatMode` 반환 |
| 장소 목록 | GET | `/api/places` | `region`, `category`, `limit` |
| 게시글 목록 | GET | `/api/posts` | `region`, `category` |
| 게시글 작성 | POST | `/api/posts` | 게시글 JSON, 성공 시 `201` |
| 게시글 상세 | GET | `/api/posts/{post_id}` | 상세 반환 및 조회수 증가 |
| 게시글 수정 | PATCH | `/api/posts/{post_id}` | 비밀번호와 변경 필드 |
| 게시글 삭제 | DELETE | `/api/posts/{post_id}` | JSON body의 비밀번호 |
| 좋아요 등록 | POST | `/api/posts/{post_id}/like` | 좋아요 수 1 증가 |
| 좋아요 취소 | DELETE | `/api/posts/{post_id}/like` | 좋아요 수 1 감소, 최솟값 0 |
| 이미지 업로드 | POST | `/api/posts/{post_id}/image` | `multipart/form-data`, 파일 1개 |
| 이미지 제공 | GET | `/uploads/{filename}` | 업로드 파일 정적 제공 |
| 챗봇 | POST | `/api/chat` | `message`, 최근 `history`, 선택 `region` |

## 6. 데이터베이스 설계

### 6.1 SQLAlchemy 연결

- `DATABASE_URL`에서 연결 문자열을 읽어 SQLAlchemy Engine을 생성합니다.
- 기본값 `sqlite:///./localhub.db`는 실행 위치와 관계없이 `backend/localhub.db`로 해석됩니다.
- FastAPI 요청마다 Session을 생성하고 응답 완료 시 닫습니다.
- 앱 시작 시 `Base.metadata.create_all()`로 없는 테이블을 생성하고 일부 컬럼을 간이 마이그레이션합니다.
- Alembic 같은 정식 스키마 버전 관리 도구는 사용하지 않습니다.

### 6.2 `places` 테이블

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `id` | Integer PK | 내부 장소 ID |
| `source_id` | String(100), Unique | 공급자 기준 고유 ID |
| `region` | String(30), Index | 권역 코드 |
| `name` | String(200), Index | 장소명 |
| `category` | String(30), Index | 카테고리 코드 |
| `address` | String(300), Nullable | 주소 |
| `latitude`, `longitude` | Float, Nullable | WGS84 좌표 |
| `description`, `image_url` | Text, Nullable | 설명·원본 이미지 URL |
| `phone` | String(50), Nullable | 전화번호 |
| `source`, `license`, `collected_at` | String | 출처·라이선스·수집일 |

### 6.3 `posts` 테이블

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `id` | Integer PK | 게시글 ID |
| `region` | String(30), Index | 권역 코드 |
| `category` | String(20), Index | 카테고리 코드 |
| `title` | String(100), Index | 제목 |
| `content` | Text | 내용 |
| `author` | String(20) | 작성자, 기본 `익명` |
| `password` | String(20) | 수정·삭제용 비밀번호, 현재 평문 저장 |
| `view_count` | Integer | 상세 조회 횟수 |
| `like_count` | Integer | 좋아요 수 |
| `image_url` | String(300), Nullable | 업로드 이미지 경로 |

## 7. 배포 및 환경변수

### 7.1 Netlify 프론트엔드

| 항목 | 값 |
| --- | --- |
| Base directory | `frontend` |
| Build command | `npm run build` |
| Publish directory | `dist` |
| SPA rewrite | `/*` → `/index.html` (`200`) |
| 필수 환경변수 | `VITE_API_BASE_URL=https://ssafy-first-project-localhub.onrender.com` |

`VITE_API_BASE_URL`은 빌드 시 포함되므로 변경 후 Netlify를 다시 배포해야 합니다. `VITE_` 변수는 브라우저에 공개되므로 비밀키를 저장하지 않습니다.

### 7.2 Render 백엔드

| 항목 | 값 |

| Health check | `/health` |

### 7.3 Render 환경변수

| 변수 | 필수 | 설명 |
| --- | --- | --- |

## 8. 비기능 요구사항 및 운영 제약

### 8.1 사용성·성능

- 데스크톱과 모바일에서 핵심 기능을 사용할 수 있어야 합니다.
- Axios 요청 타임아웃은 15초입니다.
- 지도 API 응답은 기본 200건, 최대 500건이며 카드 목록은 처음 20건만 표시합니다.
- 게시글 목록에는 페이지네이션이 없고 카테고리별 보존 제한으로 크기를 제어합니다.
- Render 무료 인스턴스의 콜드 스타트 시 첫 API 응답이 지연될 수 있습니다.

### 8.2 보안

- `.env`, API 키, DB 연결 문자열을 Git에 커밋하지 않습니다.
- OpenAI 키는 Render에만 저장하고 Netlify 또는 `VITE_` 변수에 넣지 않습니다.
- 게시글 비밀번호는 API 응답과 챗봇 컨텍스트에서 제외합니다.
- 현재 비밀번호는 교육용 요구에 따라 평문 저장·비교하므로 실제 운영에는 적합하지 않습니다.
- CORS는 허용된 브라우저 Origin을 제한할 뿐 API 인증을 대신하지 않습니다.

### 8.3 현재 구현의 중요 제약

| 항목 | 현재 동작과 영향 |
| --- | --- |
| 데이터 지속성 | Render 무료 파일시스템의 SQLite와 `uploads`는 재배포·재시작·유휴 중지 후 사라질 수 있습니다. |
| 사용자 간 공유 | 모든 프론트엔드가 동일한 `VITE_API_BASE_URL`과 동일한 DB를 사용해야 같은 게시글을 봅니다. |
| 실시간 갱신 | 다른 사용자의 게시글은 열린 화면에 자동 반영되지 않으며 새로고침 또는 재조회가 필요합니다. |
| 이미지 권한 | 이미지 업로드 API는 현재 비밀번호를 검증하지 않아 게시글 ID를 아는 사용자가 이미지를 교체할 수 있습니다. |
| 이미지 정리 | 일반 게시글 삭제 시 첨부 파일을 함께 삭제하지 않아 고아 파일이 남을 수 있습니다. |
| 좋아요 | 계정 기반 중복 방지가 없고 브라우저 `localStorage`만 선택 상태를 기억합니다. |
| 조회수 | 상세 API 호출 횟수이므로 고유 사용자 조회수가 아닙니다. |
| 챗봇 비용 | 인증·호출 제한이 없어 공개 API 남용 시 OpenAI 사용량이 증가할 수 있습니다. |
| 외부 의존 | OpenStreetMap 타일과 OpenAI 장애 시 지도 또는 챗봇 기능이 제한됩니다. |

## 10. 개선 권고

### P0 — 공유·데이터 보존

- SQLite를 무료 외부 PostgreSQL로 전환하고 PostgreSQL 드라이버를 추가합니다.
- 게시글 이미지도 외부 객체 스토리지로 옮깁니다.
- 동일한 운영 Netlify URL과 Render API URL을 모든 사용자에게 제공합니다.

### P1 — 보안·정합성

- 비밀번호를 단방향 해시로 저장합니다.
- 이미지 업로드·교체에도 게시글 비밀번호를 검증합니다.
- 게시글 삭제 시 연결된 이미지도 삭제합니다.
- 글 작성과 이미지 업로드 실패를 구분하거나 하나의 원자적 흐름으로 처리합니다.
- 챗봇 API에 호출 제한과 사용량 보호를 추가합니다.

### P2 — 사용성·확장성

- 게시글 목록에 polling, 창 포커스 재조회 또는 WebSocket을 적용합니다.
- 검색·페이지네이션과 정렬 옵션을 추가합니다.
- Vue Router의 query/params 변화를 watch하여 뒤로가기와 같은 화면 상태를 일치시킵니다.
- Alembic으로 DB 마이그레이션을 버전 관리합니다.
