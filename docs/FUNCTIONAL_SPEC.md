# 여행씰 기능 명세서

## 1. 프로젝트 범위

전국 5개 권역의 주민과 관광객이 공공데이터 기반 장소를 찾고, 회원가입 없이 경험을 공유하며, 제공 데이터 범위 안에서 챗봇의 안내를 받는 Vue 3 SPA입니다.

### 포함

- FastAPI + SQLAlchemy + SQLite 백엔드
- Vue 3 + Vue Router 프런트엔드
- 5개 권역 지역정보 조회와 Leaflet 지도 시각화
- 지역·카테고리 필터가 있는 익명 게시글 목록·상세·작성·수정·삭제
- 작성 시 설정한 평문 비밀번호 일치 확인
- `POST /api/chat` 챗봇, 최근 대화 최대 10건 전달
- Netlify/Render 배포 설정

### 제외

- 회원가입, 로그인, JWT
- 경로 안내, 날씨, WebSocket, 다국어
- 게시글 이미지, 검색, 조회수, 페이지네이션
- RAG 및 벡터 데이터베이스

## 2. 화면

| 경로 | 화면 | 주요 동작 |
| --- | --- | --- |
| `/` | 통합 메인 | 상단 최신순 게시판, 하단 지역·카테고리 지도 |
| `/explore` | 호환 별칭 | 별도 화면 없이 `/` 통합 SPA로 연결 |
| `/posts` | 호환 별칭 | 별도 화면 없이 `/` 통합 SPA로 연결 |
| `/posts/new` | 글 작성 | 카테고리·제목·내용·작성자·비밀번호 입력 |
| `/posts/{id}` | 글 상세 | 전체 내용, 수정 이동, 비밀번호 확인 후 삭제 |
| `/posts/{id}/edit` | 글 수정 | 원문 조회, 기존 비밀번호 확인 후 수정 |
| 전체 화면 | 챗봇 | 플로팅 열기/닫기, 세션 대화 유지, 모바일 전체 화면 |

## 3. 데이터와 보안

- `.env`와 SQLite DB는 `.gitignore`로 버전 관리에서 제외합니다.
- 서울·부산 데이터 인증키는 오프라인 수집기만 환경변수에서 읽으며 JSON·로그·API 응답에 포함하지 않습니다.
- SQLite URL은 실행 위치와 무관하게 항상 `backend/localhub.db`로 해석합니다.
- 게시글 응답 스키마와 챗봇 검색 컨텍스트에서 `password`를 명시적으로 제외합니다.
- CORS 허용 출처는 `FRONTEND_ORIGIN`에 쉼표로 구분해 설정합니다.
- 챗봇은 검색된 장소·게시글 최대 5개만 모델 컨텍스트에 넣습니다.
- API 키가 없을 때에도 지역정보 검색 기반의 제한된 안내 문구로 시연할 수 있습니다.

> 평문 비밀번호 저장은 교육용 RFP의 명시적 요구사항입니다. 실제 운영 서비스에서는 반드시 단방향 해시와 적절한 인증·인가를 적용해야 합니다.

## 4. 데이터 출처·라이선스

프로젝트의 `data/` 폴더에는 한국관광공사 TourAPI 4.0, 서울 열린데이터광장, 부산광역시 부산맛집정보 서비스에서 수집한 5개 권역 데이터 14,139건이 포함되어 있습니다. 백엔드 최초 실행 시 기존 샘플 장소를 제거하고 이름 품질 검사를 통과한 14,124건을 SQLite에 적재합니다.

| 권역 | 제공 파일 | 원본 항목 | 품질 검사 후 적재 |
| --- | ---: | ---: | ---: |
| 서울 | 8개 | 7,518건 | 7,512건 |
| 대전·충청 | 8개 | 1,365건 | 1,362건 |
| 구미·경북 | 8개 | 1,667건 | 1,665건 |
| 광주·전라 | 8개 | 1,393건 | 1,390건 |
| 부산 | 8개 | 2,196건 | 2,195건 |
| 합계 | 40개 | 14,139건 | 14,124건 |

### 음식점 추가 데이터

| 지역 | 공식 데이터셋 | 수집 범위 | 좌표 처리 | 라이선스 |
| --- | --- | ---: | --- | --- |
| 서울 | 서울시 일반음식점 인허가 정보(`LOCALDATA_072404`) | 영업 중 120,343건 중 1,000건(2026-07-16) | EPSG:5174 → WGS84 | 공공누리 제1유형 |
| 부산 | 부산맛집정보 서비스(`FoodService/getFoodKr`) | 전체 437건(2026-07-16) | 제공 위·경도 사용 | 이용허락범위 제한 없음 |

앱은 실행 시 외부 API에 의존하지 않습니다. `backend/tools/collect_food_data.py`가 환경변수의 인증키로 데이터를 수집하고 공통 JSON으로 정규화하며, 백엔드는 이 스냅샷을 시딩합니다. 공급자별 ID 접두사로 충돌을 방지하고, 같은 공급자의 기존 레코드는 최신 스냅샷에 맞춰 갱신·정리합니다.

각 JSON은 아래 필드로 매핑됩니다.

| 여행씰 필드 | 설명 |
| --- | --- |
| `source_id` | 원본 데이터의 고유 ID |
| `name` | 장소 또는 행사명 |
| `category` | `TOURIST`, `RESTAURANT`, `FESTIVAL`, `CULTURE`, `COURSE`, `LEISURE`, `ACCOMMODATION`, `SHOPPING` |
| `address` | 도로명 또는 지번 주소 |
| `latitude`, `longitude` | WGS84 좌표. 둘 중 하나라도 없으면 지도 마커에서 제외 |
| `description`, `image_url`, `phone` | 선택 상세정보 |
| `source`, `license`, `collected_at` | 출처·라이선스·수집일 |

TourAPI 데이터의 라이선스는 공공누리 제3유형입니다. 서울 음식점은 공공누리 제1유형, 부산맛집정보는 이용허락범위 제한 없음 조건을 따릅니다. 상세 출처와 원문 URL은 각 권역의 `SOURCE.md`에 기록합니다. 시딩은 `source_id`를 기준으로 장소를 추가·갱신하되 기존 게시글은 보존합니다.

## 5. 검증 항목

- 지역정보가 최초 실행 시 SQLite에 시딩되는지
- 서울·부산 수집기가 페이지네이션, 단건/배열 응답, 좌표 변환과 인증키 누락을 처리하는지
- 공급자별 장소가 재시딩 시 중복 없이 갱신·동기화되는지
- 게시글 응답과 챗봇 컨텍스트에 비밀번호가 없는지
- 비밀번호 불일치 시 수정·삭제가 `403`인지
- 수정 필드 누락 등 검증 실패가 공통 `422` 응답인지
- OpenAI 키가 없을 때 로컬 폴백이 동작하는지
- Vite 프로덕션 빌드가 성공하는지
- 모바일에서 내비게이션과 챗봇이 정상 표시되는지
